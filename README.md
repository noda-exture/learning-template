# learning-template — Exture Store

開発学習・タグ／アクセス解析検証向けのECサイトです。MPAとSPAで同じ商品・カート・模擬注文を操作できます。実際の課金・配送は行いません。

## 自分のCloudflareへ公開する

配布元をクローンして、自分の `workers.dev` に公開できます。[クローンから公開までの手順書](docs/cloudflare.md)を参照してください。公開先のWorker名・アカウントはGit対象外の `wrangler.local.json` に設定します。

## 起動

Node.js 22以上が必要です。現在の版は外部パッケージ不要です。

```sh
cd learning-template
npm run dev
```

- http://localhost:3000/classic/ — サーバーから毎回HTMLを取得するMPAです。
- http://localhost:3000/spa/ — 初回HTML取得後はAPIとブラウザ側ルーティングで更新するSPAです。

終了はCtrl+Cです。サーバー側のコード・設定を変更した場合は再起動します。HTML・CSS・SPAのJSはブラウザを再読み込みします。ポート変更はmacOS/Linuxで `PORT=3001 npm run dev`、PowerShellで `$env:PORT=3001; npm run dev` です。

## 実装済み

TOP／カテゴリ／検索／商品詳細／数量指定／カート追加・削除／購入確認／デモログイン・ログアウト／注文完了／注文履歴があります。MPAとSPAは同じブラウザのセッションを共有します。

デモログインは `demo@example.test` / `demo-password` です。認証の学習用であり、本番用の会員管理ではありません。注文履歴は会員単位で保存されます。

## HTMLを追加

`public/lab/my-test.html` を作成すると `/lab/my-test.html` で開けます。CSS・JavaScriptもpublic以下に置けます。file://で直接開かず、必ず開発サーバー経由で開きます。自由追加HTMLにもconfig/tagsの共通タグが自動挿入されます。EC用のdataLayerイベントは自動では追加しません。

SPAのページ追加は `public/views.mjs` のview関数にルートを追加します。商品は `public/catalog.mjs` を編集します。

## Cookieを変更

`config/lab.mjs` で名前・有効期限・HttpOnly・SameSite・Secure・Pathを設定し、再起動します。発行処理そのものは `src/app.mjs` を編集します。

初期値はlab_fpid、365日、HttpOnly、SameSite=Lax、Path=/です。SecureはHTTPS時だけ付与します。毎回同じIDを返して有効期限を更新します。既定ではDomainを指定しないホスト限定Cookieです。Cookie名・Pathを変更すると古いCookieが残るため、開発者ツールで対象Cookieを削除して比較します。SameSite=Noneの検証にはSecureとHTTPSの環境を用意します。

Cookieはブラウザの開発者ツールのNetworkやApplication / Storageで確認します。lab_sessionは別のHttpOnly Cookieで、カート・ログインを維持します。

Adobe FPID連携は未実装です。lab_fpidは動作検証用の独自Cookieです。

## 計測

EC画面はwindow.dataLayerにpage_view、view_item_list、view_item、view_cart、begin_checkout、add_to_cart、login、purchaseを追加します。GTM・GA4・Adobeなどへの外部送信は未接続です。GTM等の埋め込みはconfig/tagsの共通ファイルへ配置します。自動ページビューと併用する場合は二重計測に注意します。

MPAはDocumentの取得、SPAはfetchによる/api/stateなどの通信をNetworkで比較します。購入イベントは注文確定操作に対応し、完了ページの再読み込みでは再送しません。ただしネットワーク障害を含むイベントの厳密な一回配送を保証する仕組みではありません。

## 保存データとテスト

ローカルデータは `.data/sessions.json` に保存します。Gitの対象外です。リセットする場合はサーバーを停止し、.dataフォルダを別名に移動して起動し直します。ブラウザ側のCookieも必要に応じて削除します。ローカルサーバーは127.0.0.1でのみ待ち受けます。

```sh
npm test
```

MPA/SPAの応答、HTMLへのCookie付与、CSRF、数量チェック、ログイン必須、注文の重複防止、セッション分離を確認します。

## 構成

- src/app.mjs: 共通のリクエスト処理、HTML生成、API、Cookie、模擬注文です。
- src/server.mjs: ローカルHTTPサーバー、ファイル配信、JSONファイル保存です。
- public/views.mjs: MPA/SPA共通の画面です。
- public/spa.mjs: SPAの画面遷移・フォーム処理です。
- public/catalog.mjs: サンプル商品です。
- public/style.css: レスポンシブスタイルと商品イラストです。
- config/lab.mjs: 検証用Cookie設定です。

## Cloudflare版

Workers用エントリーポイント、静的アセット配信、SQLite-backed Durable Objectsによる永続化に対応しています。従来のローカル版とMPA・SPAの画面や操作を共有します。ローカル版の `.data/` とCloudflareの保存データは独立しています。

当初予定していたD1への移行に代わり、初回デプロイ時に保存先を自動作成でき、サイト内の操作を直列化できるDurable Objectsを採用しました。会員共有データの更新と注文の重複防止を維持する、学習向けの構成です。

公開・更新・検証方法は[Cloudflare手順書](docs/cloudflare.md)にまとめています。GitHubとの自動デプロイ連携は未設定です。

ローカル版は本番EC・個人情報の保管に使う設計ではありません。

## カート追加とHTTPステータス検証

商品ページはカート追加ボタンを1つにまとめ、その下のプルダウンで返却ステータスを選択します。初期値は200です。カート画面には自動遷移しません。「カートを見る」で移動できます。400・500・503を選択すると、サーバーが意図的に該当ステータスを返す検証機能です。実際の障害ではなく、カート変更やadd_to_cartイベントの発火はありません。

MPAは商品URLへのPOSTに対して結果付きHTMLを返すため、Documentリクエストのステータスを確認します。再読み込みによるPOST再送では再追加される場合があります。SPAは/api/addのfetch応答をその場に表示し、URLを変えず、page_view/view_itemも追加発火しません。Networkで200/400/500/503を確認してください。

## 5段階の購入フロー

カート → 送り先 → 支払い方法 → 確認 → 完了の順に進みます。未ログインの場合はカートの次にデモログインを挟みます。送り先は架空のサンプルが初期表示され、「次へ」で保存します。保存後は戻って編集できます。支払いはカード・銀行振込・代引きの模擬選択です。クーポンDEMO10は商品小計の10%を1円未満切り捨てで割り引きます。送料・手数料は0円です。

各画面に200/400/500/503の選択欄があります。カートの「送り先へ進む」・削除、送り先・支払いの「次へ」、確認の注文確定、完了の「注文履歴を見る」に適用します。エラー時は保存・削除・注文を実行せず、その画面に留まります。プルダウンの選択自体では通信しません。戻るリンクは通常のナビゲーションです。MPAの成功操作は303で次のGET（200）へ遷移し、検証エラーはPOST自体に400/500/503を返します。SPAの成功はAPIが200を返します。

送り先と支払い方法が未設定の状態で確認・購入を飛び越せないようにしています。送り先・支払いの保存時にadd_shipping_info/add_payment_infoをdataLayerへ追加し、送り先入力値は計測イベントに含めません。

## 静的ページ一覧

ECトップの「静的ページ一覧へ」、または上部の「静的ページ一覧」から `/lab/` へ移動できます。`public/lab/` 以下の `.html` / `.htm` を自動でカード表示します。サブフォルダも対象で、ファイル名順に並びます。カード名はHTMLのtitle、titleがない場合はファイル名です。サンプルは `public/lab/welcome.html` です。カードの図は共通のページアイコンで、実際の画面キャプチャではありません。

ファイルを追加・削除して一覧を再読み込みすると反映されます。サーバー再起動や一覧への手動登録は不要です。`/lab/index.html` は自動一覧用の予約URLのため、この位置に独自ページは置かないでください。独自ページから一覧へ戻る場合は `<a href="/lab/">静的ページ一覧へ</a>` を追加します。

ローカル版はサーバーがファイルを走査します。Cloudflare版はデプロイ時に一覧データを生成するため、ファイル追加・削除後は再デプロイします。

## マイページとお気に入り

マイページは注文履歴・個人情報の編集・お気に入りの3画面です。個人情報は名前・メールアドレス・郵便番号・住所・電話番号を編集できます。検証用の架空情報を使用してください。プロフィールを編集してもログイン用のデモ認証情報は変わりません。過去の注文の送り先も変更しません。保存済みの配送先がない場合に、プロフィールの住所を配送入力の初期値に使います。

お気に入りはTOP・商品一覧・商品詳細・カート・注文確認・注文履歴の商品から登録・解除でき、ヘッダーから一覧へ移動できます。未ログインでも利用できます。ログイン後は会員単位で保存され、別ブラウザでも同じ会員で取得できます。SPAではページ遷移せずボタンを更新し、入力途中のフォームを保持します。登録時にadd_to_wishlistイベントを追加します。

## 商品検索

各EC画面のヘッダーから商品検索できます。商品名・説明文・カテゴリ名を対象に、スペース区切りの複数語はすべてを含む商品を表示します。英字の大文字小文字、全角半角、ひらがな・カタカナをそろえて検索します。結果件数を表示し、カテゴリ切り替えでもキーワードを保持します。「検索をクリア」で解除できます。MPAはHTML遷移、SPAはページ内遷移です。

## 全ページ共通のタグ配置

- `config/tags/head.html`：GTMのscript、Adobe Tags等をHTMLタグごと配置します。全ページのhead開始直後へ挿入します。
- `config/tags/body-start.html`：GTMのnoscript等を配置します。全ページのbody開始直後へ挿入します。

ECのMPA・SPA、静的ページ一覧、public/lab以下のHTML、HTMLのエラー画面が対象です。JSON API・CSS・JS・画像・リダイレクト応答には挿入しません。初期状態は説明コメントのみで、外部タグの読み込みや送信はありません。共通設定したタグを個別HTMLにも配置すると二重読み込みになります。

MPAは通常のHTML読み込みごとにタグが読み込まれます。SPAは初回表示・再読み込み時だけです。SPAの画面遷移ではタグを再挿入せず、外部スクリプトを再実行しません。別タブやMPA/SPA間の切り替えは新たなHTML取得のため再び読み込みます。

ファイル保存後、ブラウザを再読み込みすると反映されます。サーバー再起動は不要です。SPAの画面内遷移だけでは変更は反映されません。個別HTMLのソースファイル自体は変更せず、配信時に挿入します。自由追加HTMLは明示的なhead/bodyを持つ通常のHTML文書を推奨します。

既存のEC用dataLayerイベントは残しています。共通タグの挿入は追加のページビューを送信しません。GTMなどでのイベント設定・自動ページビューとの重複は検証目的に応じて設定してください。共通ファイルはリポジトリに含めるため、秘密のAPIキー等は記載しないでください。

## 新規会員登録

ログイン画面から「入力 → 確認 → 完了 → ログイン」と進みます。名前・メール・8〜128文字のパスワードと確認入力に対応します。メール重複は大小文字と前後空白を正規化して確認します。各画面で200/400/500/503を選択でき、エラー時は登録しません。確認用データは30分で失効します。パスワードはソルト付きscryptハッシュで保存し、ブラウザ・dataLayerへ返しません。登録成功時のみsign_upを送ります。メール認証・送信・パスワード再発行は未実装です。

登録後は登録した情報でログインします。注文履歴・お気に入り・プロフィールは会員単位で保存され、別ブラウザでも同じ会員で取得できます。未ログインのお気に入りはログイン時に統合します。カートと配送入力はセッション単位で、ログアウト時にクリアします。ログイン・ログアウト時はセッションID・CSRFトークンを更新します。登録会員のメール変更は次回ログインに反映します。デモ認証情報は変更されません。

会員データは.data/sessions.jsonのaccounts:v1に保存します。既存のデモセッションは共有デモ会員へ移行します。複数会員の検証は新規登録で行ってください。Cloudflare版はDurable Objectsで操作を直列化し、応答ごとのトランザクションで保存します。検証用の架空情報と専用パスワードをご利用ください。
